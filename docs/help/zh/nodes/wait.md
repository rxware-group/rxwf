# Wait 节点

## 用途

**暂停**当前分支执行指定毫秒数，然后将输入 Items **原样**传递给下游。Wait 为 **动作** 节点，适合限流、等待外部系统就绪、与 Schedule 配合的简单延迟，或 Switch 多路中的错峰处理。`ms=0` 时立即透传，不阻塞。

## 端口与连接

| 方向 | ID | 说明 |
|------|-----|------|
| 输入 | main | 上游 Items |
| 输出 | main | 延迟后相同的 Items |

```
httpRequest → wait → set / httpRequest …
```

Wait 不修改 Item 内容，仅插入时间间隔。

## 参数

| 参数 | 说明 |
|------|------|
| **等待 (ms)**（`ms`） | 非负整数，默认 `1000` |

须为有限数且 ≥0；非法值导致 **E2003**（`wait requires a non-negative ms value`）。

## 常见错误

| 错误码 / 现象 | 说明 |
|---------------|------|
| **E2003** | `ms` 为负数或非数字 |
| 执行 seemingly 卡住 | 故意等待；检查 `ms` 是否过大（如误填毫秒为秒级×1000） |
| 与 Schedule 混淆 | Wait 为单次延迟；周期性触发请用 scheduleTrigger |

## 示例

### 示例 A

API 限流：HTTP 调用后 `ms=500`，避免连续请求触发 429。

### 示例 B

轮询间隔：Switch 的 pending 分支接 Wait `ms=3000` 再回连 HTTP 查询状态。

### 示例 C

零延迟占位：`ms=0` 用于画布布局或调试拓扑，行为等同直连透传。
