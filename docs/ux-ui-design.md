## 1. 设计原则与愿景

### 1.1 设计目标
创建一个直观、高效、可扩展的RX-Workflow，让开发团队能够快速构建和管理复杂的自动化流程。

### 1.2 设计理念
- **简洁直观**: 降低学习成本，用户可以快速上手
- **高效专注**: 减少干扰，聚焦于工作流构建
- **灵活强大**: 支持复杂场景，满足高级用户需求
- **视觉清晰**: 通过颜色和布局清晰传达状态和层级

### 1.3 设计风格
- 采用现代扁平化设计风格
- **默认 Dark 主题**；提供 **Light** 与 **跟随系统**（`prefers-color-scheme`）三种模式（FR-20.2）
- 所有颜色通过 **CSS 变量（Design Token）** 定义，禁止在组件内写死主题色
- 强调功能性，不过度装饰
- 参考 n8n 的设计语言，保持专业感

#### 左侧节点面板 (宽度: 240px)

- **设计规范**：背景 `--color-surface-panel`；手风琴分类；图标 20×20；标签 `--text-secondary`；hover `--color-surface-hover` + 左侧 2px `--color-accent` 高亮条。
- **分期角标**：`P1` 琥珀、`v1.1` 灰锁；不可拖拽项 tooltip 说明版本。
- **搜索**：面板顶部过滤节点名（v1.0 P1）。

**v1.0 P0（默认展开）**

| 分类 | 节点 |
|------|------|
| 触发器 | 手动、Webhook、定时、子工作流触发 |
| 数据 | Set/JSON、Merge、Switch、If |
| 网络 | HTTP |
| 代码 | **JavaScript**（沙箱，见 §3.5） |
| 逻辑 | Wait（固定时长）、Loop |
| 工具 | MCP Client |

**v1.0 P1（次要分组）**

| 分类 | 节点 |
|------|------|
| 触发器 | 错误触发器 |
| 数据 | Split In Batches |
| 文件 | 读/写文件 |
| 数据库 | MySQL、PostgreSQL、SQLite |
| AI | Ollama 对话、OpenAI 兼容、LLM 流式、Chat 触发 |
| 逻辑 | — |

**v1.1+（默认折叠 + 锁图标，不可拖入画布）**

Agent 编排、Embedding/RAG、文件变化触发、SSH/本地命令、OpenAPI 导入等。

> **刻意不在面板展示**：MongoDB、Python Code、WMI（与 spec §5.2 / 技术约束一致）。

### 4.4.1 表单控件尺寸（单行控件统一高度）

全站**单行表单控件**必须使用统一高度，通过 CSS 变量 `--rxwf-control-height` 定义（当前默认值 **36px**），与主要按钮高度（§5.1）对齐。

| 变量 | 默认值 | 用途 |
|------|--------|------|
| `--rxwf-control-height` | `36px` | 单行输入、下拉、数字步进等控件外框高度 |
| `--rxwf-control-radius` | `4px` | 输入框、下拉触发器圆角 |

**适用控件（必须 `min-height: var(--rxwf-control-height)`，`box-sizing: border-box`）**

| 类型 | 选择器 / 组件 | 说明 |
|------|----------------|------|
| 单行文本 | `input`（排除 checkbox、radio、file、hidden、`.rxwf-number-input-field`） | 参数面板、设置页、工具栏搜索等 |
| 原生下拉 | `select` | 遗留或简单枚举 |
| 自定义下拉 | `.rxwf-select-trigger` | `Select` 组件触发器 |
| 数字输入 | `.rxwf-number-input` | `NumberInput` 外框（含步进按钮） |
| 带建议的单行输入 | `.http-kv-input`、`SuggestTextInput` | HTTP Header、Ollama Model 等 combobox |
| 数据检视搜索 | `.data-inspector-search` | INPUT/OUTPUT 面板标题栏搜索框 |

**不适用（禁止套用 36px 固定高度）**

- `textarea`、Code/JSON 编辑器、多行 HTTP Body
- 画布节点工具栏等纯图标按钮（另有尺寸规范）

**实现约定**

- Token 定义于 `apps/web/src/styles.css` 的 `:root`（含 dark / light 主题块）。
- 表单字段容器内优先使用 `.rxwf-form-field-control > input` / `select` / `.rxwf-select .rxwf-select-trigger` 已有规则，**禁止**在组件内写死 `28px`、`1.75rem` 等局部高度。
- 新增单行控件时复用 `--rxwf-control-height`；若需紧凑变体须在设计评审中说明并更新本节。

### 4.7 滚动条与页内边距

全站滚动条样式由 `apps/web/src/scrollbars.css` 统一提供；页内留白由 CSS 变量控制。

#### Token

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `--rxwf-page-gutter` | `1.5rem` | 页面内容四边留白（设置 Modal 右侧详情区等同） |
| `--rxwf-scrollbar-size` | `6px` | 滑块可见宽度（`:root` 全局统一，禁止局部覆盖） |
| `--rxwf-scroll-gutter` | `var(--rxwf-page-gutter)` | 滚动条轨道宽度（与页边距一致） |
| `--rxwf-scrollbar-thumb` | 主题色 | 滑块颜色 |
| `--rxwf-scrollbar-thumb-hover` | 主题色 | 滑块 hover |

#### 布局原则

```text
┌────────────────────────────────────────────────────┐
│ pad │        内容区        │  track (--rxwf-scroll-gutter) │
│1.5rem│                     │    [6px thumb 居中]          │
└────────────────────────────────────────────────────┘
  ↑ 左 gutter = padding-inline-start     ↑ 右 gutter = 轨道宽（无 padding-inline-end）
```

- 内容左右边距**必须对称**，均为 `--rxwf-page-gutter`。
- 滚动条**不贴窗口右缘**：WebKit 轨道宽 = `--rxwf-scroll-gutter`，滑块通过透明 `border` 在轨道内居中。
- 带垂直滚动的页级容器（如 `.settings-content`、`.rxwf-scroll-region`）：

```css
padding-block: var(--rxwf-page-gutter);
padding-inline-start: var(--rxwf-page-gutter);
padding-inline-end: 0;
scrollbar-gutter: stable; /* 无滚动条时也预留右侧 gutter，与有滚动条时宽度一致 */
```

#### 编码规范

**Do**

- 可滚动区域继承全局 `scrollbars.css`。
- 页级滚动容器使用 `padding-inline-end: 0` + `scrollbar-gutter: stable`，右侧留白由稳定 gutter / 轨道宽 `--rxwf-scroll-gutter` 提供。
- 需要更窄轨道时，仅在局部覆盖 `--rxwf-scroll-gutter`（例如嵌套面板）；滑块宽度始终使用全局 `--rxwf-scrollbar-size`。

**Don't**

- 不要在页面/组件内新增 `::-webkit-scrollbar` 规则。
- 不要在 Chrome 侧同时写 `scrollbar-width`（会破坏 WebKit 伪元素，见 `scrollbars.css` 注释）。
- **禁止**局部覆盖 `--rxwf-scrollbar-size`（全站滑块宽度须一致）。
- **禁止**可滚动容器四边同值 `padding` 且轨道宽 = `--rxwf-scroll-gutter`（会造成右侧留白约为左侧两倍）。

#### 浏览器差异

- **Chrome / Edge / Safari**：完整 inset 居中效果。
- **Firefox**：`scrollbar-width: thin` + 透明轨道；滑块无法像素级居中，视觉上仍无箭头。不支持 `scrollbar-gutter: stable` 时，可对滚动容器回退 `padding-inline-end: var(--rxwf-page-gutter)`。

```
│ 主题管理                                    [+ 新建主题]                      │
├─────────────────────────────────────────────────────────────────────────────┤
│ ID          名称           继承      预览    状态    操作                       │
│ dark        深色（内置）    —        ●●●    ● 启用   [查看 Token]              │
│ light       浅色（内置）    —        ○○○    ● 启用   [查看 Token]              │

└─────────────────────────────────────────────────────────────────────────────┘
```

- **新建主题**：`themeId`、`name`、`extends`（dark/light）、Token 表单或 JSON
- **预览**：侧栏实时预览编辑器片段
- **builtin 主题**：仅可编辑「覆盖层」或禁用展示，不可删除

### 3.23 Node Runner 管理（FR-23）

#### 3.23.1 Runner 列表（v1.0-core 只读）

路径：**系统设置 → Runner**（Lite/Standard 均展示；Member 只读）。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ Runner 执行节点                                    [刷新]  (v1.1)[+ 注册 Token] │
├─────────────────────────────────────────────────────────────────────────────┤
│ 名称           平台              状态      负载      标签           类型      │
│ embedded-local linux / x64       ● 在线    0/2       —              内置      │
│ win-dc-01      windows / x64     ● 在线    1/4       domain-controller agent  │
│ dev-mac        macos / arm64     ○ 离线    —/2       dev             agent     │
└─────────────────────────────────────────────────────────────────────────────┘
```

| 列 | 展示规则 |
|----|----------|
| **平台** | `{{os}} / {{arch}}`；Tooltip 显示 `osVersion`（若有） |
| **状态** | `online` 绿点 / `offline` 灰 / `draining` 黄 + 文案 |
| **负载** | `runningJobs / maxConcurrent`；满负载时橙色 |
| **类型** | `embedded` 显示「内置」；`agent` 显示「Agent」 |

- v1.0-core：**无**删除/排水按钮；底部说明 Embedded 探测自控制面本机 OS。
- v1.1 Admin：`[+ 注册 Token]` → Modal 展示一次性 Token + `rxwf-runner register` 命令示例（按 OS 分 Tab：Windows / Linux / macOS）。

#### 3.23.2 工作流级 Runner 策略

入口：编辑器顶栏 **工作流设置** → **执行** → **Runner 策略**。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ Runner 策略                                                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│ 模式    (●) 自动匹配   ( ) 固定 Runner   ( ) 按标签匹配                        │
│ 平台筛选 (auto)   [ 任意 ▼ ]  windows | linux | macos                        │
│ 标签    (label)   [ domain-controller ] [+ 添加]                             │
│ 固定 Runner (pinned)  [ win-dc-01 ▼ ]  ← 下拉仅列出在线/离线 Agent            │
│ 无匹配时  (●) 失败 (推荐)   ( ) 回退内置 Runner                               │
└─────────────────────────────────────────────────────────────────────────────┘
```

| 规则 | UI |
|------|-----|
| `pinned` + Runner 离线 | 保存时 **警告** E1010（不阻断草稿）；Active 时 **错误** |
| `preferRemote` 节点（如 WMI） | 若选「回退内置」→ 校验失败 E1011 |
| `auto` + 平台筛选 | 与节点 manifest `platforms` **取交集** 后再调度 |

#### 3.23.3 节点级 Runner 覆盖

节点属性面板 → **高级** → **执行 Runner**（默认折叠）。

```
┌─ 执行 Runner ─────────────────────────────────────────┐
│ 模式  [ 继承工作流策略 ▼ ]                             │
│       inherit | auto | pinned | label                 │
│ 平台  [ windows ▼ ]   (仅 auto/label 时可选)          │
│ 标签  [ domain-controller ]                           │
│ 固定  [ win-dc-01 ▼ ]   (仅 pinned)                  │
│ ℹ 此节点需要: windows + wmi（来自节点类型）            │
└───────────────────────────────────────────────────────┘
```

- 节点 manifest `runnerRequirements` 以 **只读提示条** 展示（平台图标：Win / Tux / Apple）。
- 执行历史节点详情 Drawer：展示 **实际 Runner**（`runnerId` + `platform` 快照），见 openapi `ExecutionDetail.nodeRuns`。

### 3.24 设置 Modal 详情页（标题层级）

路径：全局 **设置** Modal → 左侧 Nav → 右侧详情区（`.settings-content`）。

#### 标题层级

| 层级 | HTML | 文案来源 | 组件 |
|------|------|----------|------|
| 一级（页标题） | `<h1 class="settings-page-title">` | 与左侧 Nav `labelKey` **同源**（`settings-nav-config.tsx`） | `SettingsPageShell` |
| 二级（配置分块） | `<h2 class="settings-section-title">` | 各 panel 小节 i18n key | `SettingsSection` |

```text
┌─ Nav ─┬─ 详情 ─────────────────────────────┐
│ ● 我的 │  我的                    ← h1      │
│       │  ┌─ 账户信息 ────────┐   ← h2      │
│       │  │  ...              │             │
│       │  └───────────────────┘             │
└───────┴────────────────────────────────────┘
```

#### 编码规范

**Do**

- 新增 settings 子路由页面**必须**使用 `SettingsPageShell`。
- 多个配置分块**必须**使用 `SettingsSection`（或等价 `h2.settings-section-title` + `.panel`）。
- 子路由不在 Nav 中时，通过 `titleKey` / `title` 显式覆盖页标题（如 `/settings/models/ollama`）。

**Don't**

- 禁止手写与 Nav 重复的 h1 文案。
- 禁止在页内用 `h3` / `h4` 作为分块标题（保持 h1 → h2 两层）。

#### 参考实现

- 组件：`apps/web/src/features/settings/SettingsPageShell.tsx`
- Nav 标题解析：`use-settings-nav-title.ts` + `findSettingsNavItem()`
- 样式：`apps/web/src/styles.css`（`.settings-page-title`、`.settings-section-title`、`.settings-content`）
- 完整规范：[settings-page-layout.md](./settings-page-layout.md)

### 6.6 危险操作确认（spec §11.7，v1.0）

| 操作 | 确认形式 |
|------|----------|
| 删除工作流 / 凭证 / 知识库 / MCP Token | Modal + **输入资源名称** |
| 工作流设为 **Active** | Modal：后果说明 + Production Webhook URL 摘要 |
| NL/IDE Diff 应用到 **已 Active** 工作流 | 勾选「我确认变更生产定义」 |
| 禁用插件 | Modal：选择「停止运行中实例」/「等待完成」 |
| 批量停止执行 | Modal + 影响实例数 |
| MCP Token 绑定 prod 的 publish | 同 Active 级确认 |
| 吊销 Runner / 排水 | Modal：列出在途任务数；排水可取消 |

统一使用 **危险按钮**（§5.1）；主按钮为「取消」，确认在左（防误点）。

### 6.7 全局反馈层级

| 层级 | 用途 | 示例 |
|------|------|------|
| **Toast** | 非阻塞成功/轻量失败 | 保存成功、复制 URL |
| **Inline Banner** | 页面级持久提示 | Active 工作流未保存、草案未发布（NL） |
| **Modal** | 需用户决策 | 删除、Active、回滚 |
| **Drawer** | 详情浏览 | 执行节点 I/O、插件 manifest |

默认 Toast 3s；错误 Toast 需手动关闭或 8s。

## 7. 响应式设计

### 7.1 断点定义

| 断点 | 宽度 | 布局调整 |
|------|------|----------|
| 超大屏 | ≥1920px | 面板加宽, 更多工具栏选项 |
| 大屏 | 1440-1919px | 默认布局 |
| 中屏 | 1024-1439px | 右侧面板可折叠 |
| 小屏 | <1024px | 单列布局, 移动端优先 |

### 7.2 编辑器响应式

> v1.0 **仅支持 Web 桌面**（spec NFR-5：最佳宽度 ≥1280px），不做移动端编排适配。

- **≥1440px**：完整三栏布局
- **1024–1439px**：右侧属性面板可收起
- **<1024px**：全屏提示「请使用桌面浏览器访问（宽度 ≥1024px）」；只读查看执行历史可选 P2
